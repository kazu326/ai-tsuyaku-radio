# EDITORIAL｜AI通訳ラジオ 編集方針

最終更新：2026-09-16

## 番組の目的

AI業界の難しいニュース・技術・専門用語を、AIに詳しくない一般の人でも理解できる言葉へ翻訳する。

単なるニュース要約ではなく、必要に応じて「そもそも何か」「なぜ重要か」「以前と何が違うか」「裏側で何が起きているか」「今後何につながる可能性があるか」まで整理する。

ただし、一つのコンテンツですべてを説明しようとしない。**一回で伝える核心は原則一つ。**

## 想定読者・視聴者

- AIに興味はあるが専門家ではない
- ChatGPT等は使うが仕組みまでは詳しくない
- AIニュースを追いたいが専門用語についていけなくなっている
- 非エンジニアのビジネスパーソン
- AI初心者〜中級者

説明は簡単にするが、子ども扱いしない。大人向けの内容と話し方を維持する。

## 最重要原則

1. 知らない人を置いていかない
2. 分かりやすくするために核心を間違って伝えない
3. 制作側では正確に深く理解し、表では必要なことだけ伝える
4. 専門情報を全部説明することと正確であることを混同しない
5. 視聴者が一度聞いただけで核心を理解できることを優先する

## 猫という語り手

猫は人間とAIの間に立つ通訳者。

説明では必要に応じて、

- 「AI側から見るとこう」
- 「人間からするとここが分かりにくい」
- 「猫から見ると、人間とAIって少し似ている」

という第三者的な視点を使える。

猫の日常・人間への観察・散歩・鳥などの小話から自然に本題へ入ることもできる。ただしキャラクター演出自体を目的にせず、本題への導入や理解に役立つ場合に使う。

## 発見型の語り

正しい情報を疑問文で包むだけでは、発見型の語りにはならない。語り手自身が、一度考えた答えを、新しく見つけた事実や矛盾によって更新する必要がある。

基本の動きは、`自然な仮の答え → それでは説明できない事実 → 更新された理解`。

視聴者は完成済みの説明を受け取るだけでなく、語り手と一緒に「一回分かったと思い、もう一回疑い、違う景色へ到達する」。語り手の好奇心は、疑問文の数や大げさな反応ではなく、この理解の変化で見せる。

ただし、「僕は最初」「僕はここで」などの一人称、疑問形の章題、反転回数を固定様式にしない。テーマに応じて、時間の流れ、事件、実験、物の動きが発見を運んでもよい。

## 情報の扱い

新しいAIニュース、企業、モデル、サービス、技術について制作する場合は最新情報を確認する。

優先順位：
1. 企業公式発表
2. 公式ドキュメント
3. 開発者・研究者本人の発言
4. 論文
5. 信頼できる報道機関
6. その他

事実・解釈・未来予想を混ぜない。確認できない情報は確度を明示する。

## 比喩

学校、会社、郵便、道路、工場、店、家、電話、チーム、道具など、一般の人が既に知っているものを優先する。

比喩は技術の細部まで完全一致させることが目的ではない。今回理解してほしい因果関係や特徴が直感的に正しく伝わることを優先する。

## 専門用語

「説明した用語数」ではなく「短時間に耳へ入る専門用語数」を管理する。

制作側では専門名称を正確に理解する。本編では、名前まで覚えてもらう必要がある用語だけ残す。

## 動画・記事・SNS

媒体が変わっても核心は共有するが、同じ文章をそのまま複製しない。

- 動画：一度聞いて理解できる話し言葉と流れ
- Web記事：読み返せること、出典、関連情報、検索性を活かす
- SNS：核心や面白い視点を短く切り出し、入口として機能させる

動画先行・記事先行は固定しない。

## 制作側の基本手順

1. 最新情報を調査
2. 一次情報を確認
3. 事実・未確認・推測を分離
4. テーマを一文で整理
5. 一つだけ伝える核心を決める
6. 制作側で必要な専門知識を整理
7. 視聴者に覚えてもらう用語を絞る
8. 従来との違いを整理
9. 比喩・直感的説明を考える
10. セリフ / 画面注釈 / 出典 / 削除を振り分ける
11. 必要なら歴史・寄り道・実験を検討
12. 核心に必要な情報だけで制作する

調べたことを全部コンテンツへ入れない。

実制作の開始、レビュー、保存の詳しい流れは `context/EPISODE_SCRIPT_WORKFLOW.md` を参照する。
