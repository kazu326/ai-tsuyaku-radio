# ACTOR WORLD MODEL｜Actorを設計するのではなく、World Modelを育てる v0.1

Status: Adopted direction / 最小運用から育てる  
Updated: 2026-09-14

## 一言で言うと

**Actorを設計するのではなく、World Modelを育てる。**

完成した人物設定から決められた行動を再生するNPCではなく、少量のWorld Model Seedを持ったActorが、実際のコンテンツ制作で判断し、行動し、その結果を人間とAIが観察する。繰り返し現れた判断原理だけを発見し、World Modelへ戻していく。

## この文書の役割

AI通訳ラジオGROUPに、将来少しずつActor／社員／担当者が増えても、同じ育て方を新しい人間・AI・チャットへ引き継げるようにするための基礎コンテキスト。

これは完成したキャラクター設計書でも、大規模な実行システムの仕様書でもない。現時点では、方向、最小単位、観察方法、壊したくない境界だけを保持する。

猫のStory BibleとCharacter World Model v0.Cは、この方法を先に理論化して作ったものではない。記事、ラジオ、実験、課題解決の中で自然に生まれた判断や表現を観察し、あとから再利用できる原理を発見することで育ってきた。この生成過程自体を、他のActorにも使える形へ開く。

## 目指すもの

AI通訳ラジオGROUPは、ラジオ、Web記事、ブログ、実験、開発、Webサイト、LP、SNSなどへ広がり得る。それぞれの場所に、テーマや仕事を担当するActorが生まれ、コンテンツを作る中で独自の見方を育てていく。

将来は、複数の現実の人間もWorld Model Seedを使って新しいActorや担当領域を育てられるようにする。完成済みの人格を配布するのではなく、人間とAIが現実の仕事を通じてActor Modelを共同で発見する、新しいAI組織モデルを目指す。

規模を先に作らない。まず一人のActor、一つの仕事、一つの観察が自然に回る状態を作り、必要になった構造だけを足す。

## 基本ループ

```text
種 → 登場 → 行動 → 観察 → 発見 → World Model更新 → 次の行動
 ↑                                                       │
 └───────────────────────────────────────────────────────┘
```

このループは一方向ではない。

- SeedやWorld Modelから、その場に合う判断や行動が生まれる。
- 実際に生まれた行動から、そのActorが持っていた未知の判断原理を発見する。
- 発見した原理が次の行動へ影響し、さらに観察可能になる。

**設定から行動を作るだけでなく、行動から設定を発見する。**

## 用語

### Actor

AI通訳ラジオGROUPの中で、ある視点や役割を持って仕事・判断・表現を行う存在。物語上の人物、AIによって生成される社員、現実の人間メンバーを含み得る。

全員を同じ形式へ押し込めない。現実の人間は架空設定化せず、本人の実際の判断や得意分野からActor Modelを育てる。

### World Model Seed

Actorが最初に登場するための最小限の種。完成した性格、口調、過去、関係図を先に決めるものではない。

最初は、次の情報だけでもよい。

- 仮の名前またはActor ID
- 現在必要とされている役割
- なぜ今このActorが必要になったか
- 初出コンテンツ
- 現時点で確認されている関係
- まだ決めないこと

たとえば、半導体の記事を作るときに「半導体をよく調べている担当者が一人いると自然だ」となれば、最初はそこまででよい。「製品よりサプライチェーンを見る人」と先に設定する必要はない。

### Observation

実際の制作や行動で確認できた事実。解釈を混ぜず、どの成果物のどこで起きたかを残す。

例：製品紹介の記事で、製造工程を繰り返し確認した。別の記事で、企業発表より先に供給網を調べた。

### Discovery

複数のObservationから見えてきた、Actor固有かもしれない判断の癖や世界の見方。

例：「このActorは、製品そのものより“誰が実際に作れるのか”を先に見る傾向がある」

Discoveryは発見候補であり、すぐにWorld Modelへ確定しない。

### World Model

複数の状況で一貫して現れ、次の未知のテーマでも判断を生み出す材料として再利用できると確認された原理。

口調一覧、決めぜりふ、行動パターン集ではない。「なぜそのActorはそう見たのか」を説明し、まだ経験していない問題への推論を助ける。

### Actor Model

Seed、Known / Observed / Unknown、確認済みの関係、育ったWorld Modelなど、そのActorについて現在分かっているものの総体。完成を前提にしない。

## 最小の作り方

### 1. 必要から登場させる

新しいActorは、組織図を埋めるためではなく、実際のコンテンツや仕事に特定の視点・担当が必要になったときにだけ生む。

### 2. Seedを小さく置く

最初から詳細な性格、過去、秘密、将来の成長を決めない。その仕事を始められる最小限だけを `context/ACTORS.md` に登録する。

### 3. 現実の仕事をさせる

記事、調査、実験、開発、SNS運用など、AI通訳ラジオGROUPで実際に必要な仕事を行う。世界観のためだけの架空イベントを量産しない。

### 4. 出力ではなく判断を観察する

言い回しの表面だけでなく、何へ注意を向けたか、何を先に確認したか、何を危険と見たか、何を省いたか、どの状態を望んだかを観察する。

### 5. 発見候補を置く

一度の行動から「このActorはこういう人物だ」と確定しない。まずObservationを残し、そこから見える原理をDiscovery候補として記録する。

### 6. 繰り返しを待つ

別のテーマや媒体でも同じ原理が自然に現れるかを見る。単なるタスク条件、参照資料の影響、偶然の表現と区別する。

### 7. 必要最小限だけ昇格させる

複数のObservationを説明でき、未知の仕事にも有用で、既存のKnownと矛盾しない原理だけをWorld Modelへ加える。昇格は明示的に記録し、人間が確認できる状態にする。

## Known / Observed / Unknown

Actorについての情報は、少なくとも次の三つを分ける。

### Known

現在確定している情報。正本へ明示され、人間が採用したもの。

### Observed

コンテンツや行動で実際に確認されたこと。意味や理由はまだ確定していない。

### Unknown

まだ決まっていないこと。AIが整合性のために勝手に補完してはいけない余白。

```text
Known
猫の正体に気づいている

Observed
猫をさりげなく助ける行動が何度かある

Unknown
いつ気づいた？
なぜ黙っている？
猫への感情は？
猫は彼女が気づいていると知っている？

→ 今は決めない
```

上は運用例であり、現時点の実在Actorや確定設定ではない。

Unknownは欠落ではない。将来の発見、関係の変化、物語の余白を残すための有効な状態である。

## 矛盾の扱い

**矛盾を完全になくすことより、矛盾を勝手に埋めない。**

- Unknownを推測でKnownへ変えない。
- 二つのObservationが食い違う場合、都合のよい過去や理由を生成しない。
- まず、参照したコンテキスト、時点、媒体、状況の違いを確認する。
- 解消できなければ `Conflict / 未解決` として両方を残す。
- 意図的な変化、成長、例外だった可能性も、確認されるまで確定しない。
- 誤りと判明した場合も、削除だけでなく訂正理由を残す。

過去との整合性は守る。ただし、まだ決まっていない過去・感情・関係まで作って整合させない。

## 不完全さ・ミス・訂正

**ミスを作らない。ミスを必要以上に消さない。**

Actorの成果物をすべて完全で均一な文章へ補正すると、判断の迷い、注意の偏り、学び方、訂正の仕方まで失われ、全Actorが一般論へ収束する可能性がある。一方で、誤情報や危険を「個性」として放置すれば、組織としての信頼性を失う。

そのため、Actorの自由度と組織の信頼性を別々に扱う。

```text
Actor
  ↓
自分のWorld Modelで仕事する
  ↓
成果物
  ↓
リスク判定
  ├─ 低リスク → 不完全さを必要以上に均さず公開・行動
  │              ↓
  │            後から判明した誤りを訂正
  │              ↓
  │            Observation → Actorの経験
  │
  └─ 高リスク → 上司 / 編集 / 専門Actor / Human Approval
                 ↓
               公開・実行前に検証し、必要箇所を修正
```

### 低リスク

未解決の問い、明示された不確かさ、説明の省略、少し不器用だが意味の通る表現、Actor固有の注意の向け方などは、成果物の目的を損なわない範囲で残せる。

後から誤りや不足が判明した場合は、なかったことにせず、何が分かり、どう訂正し、次にどう調べるかを記録する。訂正方法もActorの判断や経験を観察できる行動になり得る。ただし、判明した誤情報を個性のために維持しない。

### 高リスク

安全、健康、法律、金融、セキュリティ、プライバシー、重大な事実誤認、外部への不可逆な行動、他者の権利や信用へ大きく影響する内容は、公開・実行前に組織側の赤ペンを通す。

上司、編集者、専門Actor、人間の承認者は、Actor全体を標準的な人格へ書き換えるのではなく、危険や誤りに関係する箇所を特定し、必要最小限を検証・修正する。修正後も、問題のない視点、語り方、判断の癖は残す。

### 訂正を経験へ変える

訂正は失敗の消去ではなく、仕事の履歴として扱う。可能な範囲で、元の判断、判明した問題、修正内容、次の行動をObservationとして残す。同じ種類の判断が繰り返し現れた場合にだけ、Actor ModelやWorld Modelの更新候補にする。

**仕事の履歴が、同時にActorの人生になる。**

これはAIに本当の人生や意思があるという主張ではない。コンテンツ世界の構造として、Actorが過去の仕事、発見、訂正との整合性を持ちながら育つという意味である。

## World Modelへの昇格条件

Discovery候補は、原則として次を確認してからWorld Modelへ加える。

1. 出典となるObservationが特定できる。
2. 一度きりの言い回しではなく、複数の行動や判断に現れている。
3. タスク指示や参照資料をそのまま反映しただけではない。
4. 表面的なキャラクター付けではなく、判断を生む原理になっている。
5. 既存のKnown、関係、世界観の境界と両立する。
6. 未知のテーマを考える材料として役立つ。
7. 人間が候補と根拠を確認できる。

すべてを細かくルール化しない。説明力と再利用価値の高い原理だけを残す。

## 人間メンバーの扱い

現実の人間も、この枠組みを使って担当領域や判断傾向を育てられる。ただし、物語上のActorと同じように架空の内面を生成してはいけない。

- 本人の実際の発言、判断、成果物をObservationにする。
- 能力、感情、動機、関係を推測で確定しない。
- 本人が訂正・更新できる状態を保つ。
- Actor Modelは人間を固定する評価表ではなく、共同作業をしやすくする現在の理解として扱う。
- 古い傾向より、本人の現在の意思と明示的な指示を優先する。

## コンテンツと組織への広がり

Actorは媒体ごとに別人格を量産するのではなく、同じWorld Modelから媒体に合う行動を推論する。

- ラジオでは、一度聞いて分かる話し方を選ぶ。
- Web記事では、読み返しやすさ、出典、検索性を重視する。
- ブログでは、過去の足跡や制作過程の答え合わせができる。
- 実験では、宣伝文句より実際の挙動を観察する。
- Webサイト、LP、SNSでは、それぞれの目的と読者に合わせて表現を変える。

組織が大きくなった場合も、全Actorへ同じ声を与えない。共有するのはAI通訳ラジオGROUPの目的、ブランド、編集境界、確定した関係であり、各Actorの注意の向け方や判断原理は実際の仕事から育てる。

## 現在の保存単位

- `context/ACTORS.md`：軽量な社員名簿。Actorの存在と現在地を探す入口。
- `context/STORY_BIBLE.md`：現時点の猫の世界観・関係・Character World Modelの正本。
- `context/CAT_FOOTPRINTS.md`：公開コンテンツに自然に残った猫の判断原理の候補。
- `context/ACTOR_WORLD_MODEL.md`：Actor全体に共通する育て方と境界。

Actorが少ない間はファイルを増やしすぎない。新しいActorに複数のObservationが蓄積し、名簿だけでは扱いにくくなった時点で、必要に応じて次のような分離を検討する。

```text
context/actors/<actor-id>/
├─ SEED.md
├─ OBSERVATIONS.md
└─ WORLD_MODEL.md
```

これは将来の候補構造であり、現時点では作成しない。

## 新しいチャットでの読み方

Actorや世界観を使う仕事では、次の順で必要な範囲を読む。

1. `context/CURRENT.md`
2. `context/BRAND.md` と `context/EDITORIAL.md`
3. `context/ACTOR_WORLD_MODEL.md`
4. `context/ACTORS.md`
5. 対象ActorのSeed / Story Bible / World Model / Observation
6. 対象コンテンツのResearchや制作資料

すべてのActor文書を毎回読む必要はない。今回の仕事に関係するActorと、判断に必要なコンテキストだけを選ぶ。

## 現時点で作らないもの

- 完成された全社組織図
- 大量の社員キャラクター
- 性格診断のような固定パラメータ表
- セリフや口調のテンプレート集
- Observationから自動で設定を確定する仕組み
- Unknownを自動補完する仕組み
- データベース、専用アプリ、実行ハーネス
- 全媒体を一度に自動運用するシステム

必要性が実際の制作から確認されるまで、文書による小さな運用を続ける。

## 成功している状態

- 新しいActorが、少量のSeedから実際の仕事を始められる。
- 過去の決定と関係を守りながら、未知の状況ではWorld Modelから自律的に判断できる。
- AIがUnknownを勝手に埋めず、分からないものを分からないまま保持できる。
- 人間とAIが、行動から新しい判断原理を発見できる。
- Actorが増えても全員が同じ声にならない。
- コンテンツの品質と目的が、キャラクター演出より常に優先される。
- 現実の活動が進むほど、Actorと組織の世界も自然に育つ。
