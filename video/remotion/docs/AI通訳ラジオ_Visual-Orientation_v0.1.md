# AI通訳ラジオ｜Visual Orientation v0.1

## 1. 目的

AI通訳ラジオの映像は、音声の代わりではありません。

音声だけでも内容が理解できることを前提に、**見たときに理解が速くなり、少し見続けたくなる映像**を目指します。

映像の目的は、派手さや装飾ではなく、関係・違い・流れ・数量差・実物イメージ・話の現在地を分かりやすくすることです。

## 2. 最重要原則

Visualは、まず「何を理解してほしいのか」から決めます。

「画面が寂しいから何か置く」ではなく、**この瞬間、映像があることで何が分かりやすくなるのか**を基準にします。

映像を追加しても理解が変わらない場合は、背景だけでも構いません。

## 3. YouTube向けの見た目

企業の社内資料、役所資料、会議用スライドのような、

- 四角い箱と文字だけが連続する
- 同じレイアウトが長く続く
- 情報は正しいが見ていて単調
- 「資料を読んでいる」感覚が強い

状態には寄せません。

一方で、派手なトランジション、過剰なアニメーション、常に動く装飾、理解と関係のない画像、視聴維持だけを狙った刺激も目的にしません。

目指すのは、**落ち着いているが、画面に小さな変化と発見があり、YouTubeとして見続けやすい状態**です。

## 4. Visual Typeは目的から選ぶ

Visual Typeを先に固定しません。

理解目的に応じて、AIが次のような候補から選びます。

- Text / Short Panel：一文の核心、短い対比、役割分担
- Comparison：AとBの違い、従来と新方式
- Flow / Diagram：処理の順番、関係、循環、役割
- Bar / Quantity Visual：速度差、数量差、規模感
- Real Image / Real Video：実物を見ること自体が理解に役立つ場合
- Generated Image / Illustration：比喩・概念・情景を一目で理解させる場合
- Background Only：音声をそのまま聞かせた方が理解しやすい場合

## 5. 画像生成の扱い

Image2など、利用可能な画像生成手段を使って構いません。

ただし、**画像生成を使えるから使う、ではなく、理解を助ける場合に使う**ことを原則とします。

例えば、学校の比喩を一枚で見せる、複雑な概念を人物・場所・動作へ落とす、実写素材がないが情景イメージが理解に有効、といった場合は生成画像が有効です。

一方、3箱と矢印だけで十分理解できる、実物画像の方が正確、画像を置くと逆に情報量が増える場合は、無理に生成画像を使いません。

## 6. 実物・概念・比喩の使い分け

- 実物を知ることが重要 → 実物画像・公式素材・既存素材を優先
- 関係や流れが重要 → Remotion図解を優先
- 数量差が重要 → Bar / Comparisonを優先
- 頭の中にイメージを作ることが重要 → 比喩画像・生成画像・簡単な映像を検討
- 音声だけで十分 → Background Only

## 7. Meaning Cluster / Visual Segmentとの関係

Visualは、Meaning Cluster / Visual Segmentの構造に従います。

同じVisual Segment内では、**外枠を維持し、中身だけ更新する**ことを基本とします。

意味と注意が連続しているのに、毎回パネルを閉じる、毎回SEを鳴らす、毎回別のVisualを新規Entryすることは避けます。

一方、同じテーマでも、具体例から抽象化へ移る、長い間が空く、背景に戻って別説明を挟む、視聴者の注意が一度リセットされる場合は、新しいVisual Segmentとして開き直して構いません。

## 8. 変化の作り方

飽きにくさは、刺激の量ではなく、**意味に沿った小さな変化**で作ります。

例えば、文字色を変える、箱の強調位置を順に変える、中身をFadeで更新する、1枚の図を段階的に完成させる、Background → Diagram → Backgroundと切り替える、同じ比喩の情景を少しずつ変化させる、などです。

## 9. 素材不足の判断

台本・Visual Planを作った時点で、AIは次を判断します。

1. 既存素材で足りる
2. Remotion図解で足りる
3. 新しい画像があると理解しやすい
4. 新しい動画があると理解しやすい
5. 素材を追加しても理解は変わらない

3または4の場合は、**不足している理由と、どんなVisualが必要か**を先に示します。

必要であれば2〜3案を提案し、人間が選べるようにします。

## 10. AIに任せる範囲

AIは、既存の共通文法に沿う限り、Visual Typeの選択、図解の具体的なレイアウト、文字色や強調順、Segment内のUpdate方法、既存素材を使うかどうか、画像生成が必要かどうかを自律的に判断して構いません。

細かな配置を毎回人間へ確認する必要はありません。

ただし、新しい大きなデザイン方針、ブランドキャラクターの変更、新規の継続的な演出ルール、誤解を生む可能性のある比喩、重要な実物画像の代替として生成画像を使う判断などは、人間への確認を検討します。

## 11. 最終確認

- 音声だけでも内容が成立しているか
- Visualによって理解が速くなったか
- 企業資料・役所資料のような単調さになっていないか
- 逆に派手すぎて音声を邪魔していないか
- 同じSegment内で不要な開閉をしていないか
- 画像・動画を「使えるから」という理由だけで追加していないか
- 重要な説明に必要なVisualが不足していないか
- 見続けたときに、小さな変化とリズムがあるか

## 12. 判断原則

Visual設計で迷った場合は、**理解 → 音声を邪魔しない → 意味構造との一致 → 認知の連続性 → 見続けやすさ → 演出**の順で判断します。

「YouTubeっぽくする」ことを、派手にすることと同義にしません。

**分かりやすく、少し見ていたくなる。**

これをAI通訳ラジオのVisual Orientationとします。
