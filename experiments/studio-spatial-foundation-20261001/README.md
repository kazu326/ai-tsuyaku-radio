## 以前の制作物の扱い（一括不採用時点の履歴）

今回の相談で作ったHiggsfield画像13枚・動画25本（先行6本＋追加19本）、派生画像・静音版、Three.jsとBlenderのスタジオ試作は、すべて番組用素材として不採用。削除せず、配色・素材感・雰囲気の参考として残す。生成ジョブの完了状態や費用は過去の事実として維持し、採用状態だけ更新する。

前回の3Dモデルも、正しい配置として承認されたものではない。形状を再利用する場合も、新しい平面図に合わせて配置・向きを見直す。前回の画像を複数枚つなぎ合わせて間取りを推測しない。

既存の正式ヒーロー・ロゴ・猫素材・既存番組はこの不採用判断の対象外。既存WebとRemotionから今回の素材パスへの参照は検索で見つからなかったため、組み込み側の変更は行わない。

`asset-policy.json` が現行の採用方針と参考ファイル一覧。旧素材フォルダのmanifestにも全件不採用・参考専用を記録した。生成先サービスの素材は変更していない。これはローカルの採用記録であり、編集ソフトの自動使用禁止機能ではない。

## 旧ブース配置案（現在はユーザー作成に変更）

ユーザーの選択により、簡易平面図で配置を決める。`layout-proposal.png` は確認用の案、`layout-proposal.json` は座標・向き・確認条件。配置はまだ確定していない。

- 部屋は仮に6×5m。北側にホスト席、ホストは南向き。
- PCはホストから見て右（西）、マイクはホストから見て左（東）。
- PC画面・キーボードはホスト側を向く。正面撮影でPC背面、後方撮影で画面側が見える。
- 扉は西壁の南寄り、窓は北壁。窓の向こう側の空間は今回未確定。
- この左右・扉位置・寸法は新案の提案であり、以前の画像から確定した事実ではない。

反対側から撮れば画面上の左右が入れ替わるのは自然。問題は同じ物体が世界座標上で移動・反転したり、別の壁に扉や窓が出現したりすること。画面上の左右だけで不整合を判断しない。

## 進め方と確認条件

1. この平面図で机・ホスト席・PC・マイク・扉・窓の位置と向きを決める。
2. シンプルな形状で一つの3Dシーンを作る。質感は最低限にする。
3. 家具と建築の座標・向きを固定し、カメラだけ変える。
4. 正面・後方・西側・東側の4枚と俯瞰図を同じ状態から出力し、位置・機材の向き・扉と窓の壁を照合する。
5. 配置の確認が済んでから、必要な動画用カメラ移動や控えめな素材調整へ進む。

生成AIによる別アングル画像は、配置の確定や検証には使わない。将来生成AIで仕上げる場合も、空間の維持は別途確認が必要。Higgsfieldクレジットを使う生成や新しい完成動画は、この方針変更の段階では行わない。
