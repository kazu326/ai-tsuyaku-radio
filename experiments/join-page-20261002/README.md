## 目的

非エンジニアの新しいReal Memberが、迷わずに「最初の1周」へたどり着けるようにする。

## 位置づけ

実際の採用募集ではないため、「採用ページ」ではなく **入社案内／体験オンボーディング** として扱う。

- 世界観としては「入社」
- 実態としては「仕組みの紹介」と「招待済みReal Memberの入口」

手順・条件・注意事項は演出せず、事実だけを書く。将来、実際に募集を始める場合も、この位置づけから発展させられる。

## 前提となる決定（2026-10-02）

- **参加条件は未定。** このページは仕組みの紹介と、招待された人への案内に限る。
- **参加希望の受付はまだ行わない。** 応募ボタンやフォームは置かない。
- **動画は先にv2へ更新する。** 既存の4:05動画は旧定義（Seed＝全員に共通の種）で構成されているため、そのままは載せない（後述）。
- 手順の正本は `docs/REAL_MEMBER_ONBOARDING.md` のまま。ページ側に手順を書き写さない。

## 5つの層の役割分担

| 層 | 役割 | 読む人 |
|---|---|---|
| 入社案内ページ（このページ） | ワクワクさせる・迷わせない | 新人、興味を持った人 |
| オリエンテーション動画 | 仕組みを理解する | 新人 |
| `docs/REAL_MEMBER_ONBOARDING.md` | 実際に手を動かす | 新人 |
| `AGENTS.md` | AIが作業ルールを理解する | Codex / Claude |
| `context/WORLD_MODEL_SEED_SYSTEM.md` | 裏側の設計 | 設計・実装担当 |

新人が最初に覚える用語は2つだけにする。

- **World Model Seed** — あなたと一緒に仕事をしながら育つAI
- **World Model Seed System** — そのAIを育てる、会社側の仕組み

Task Contract、Challenge、Observation、World Modelなどの名前は、新人に覚えてもらわない。AI側が `AGENTS.md` 経由で扱う。

## 実装するときのメモ

- ルートは `/join` を想定。参加条件が決まるまでナビゲーションには追加しない案（未決定）。
- 手順のコマンドと最初のプロンプトは、`docs/REAL_MEMBER_ONBOARDING.md` をビルド時に読み込んで表示する。エピソード記事が `episodes/*/article.md` を読み込むのと同じ方式。
- 進み具合（チェックボックス）はブラウザのlocalStorageに保存する。保存できない環境でも表示が崩れないようにする。
- 既存サイトと同じく `noindex` を維持する。
- BRAND.mdに従う。白ベース、ネイビー、アンバー。カードやボタンに角丸を付けない。汎用的な「AIサービス風」の装飾を足さない。
- 猫のセリフは `context/STORY_BIBLE.md` に従う。語尾や猫ネタで猫らしさを出さず、「どういう状態になればいいか」を先に見る視点で話す。

## 動画v2（4:05版の作り直し）

### 現行動画の構成と問題

| 時間（目安） | 内容 | 問題 |
|---|---|---|
| 0:00〜1:12 | 「World Model Seedとは何か」。共通の種＋水（Domain/Role）＋光（Persona）＋肥料（Human Signature）→ 個体AI | Seedを「全員に共通の種」として説明している。採用した定義では共通部分は World Model Seed System |
| 1:12〜2:24 | 「4層で考える」。Seedは共通、RoleとPersonaは設計、Signatureは一緒に育てる | Persona（人格）を層にしている。採用した定義では「Seedは人格ではない」。人格・外見はActor層 |
| 2:24〜3:52 | 「経験を昇格させて育てる」。日々のフィードバック → 共通意味文法 → Promotion Harness → World Model | 共通意味文法、Promotion Harness、Human Signatureはリポジトリにない用語。ACTOR_WORLD_MODELの流れと一致しない |
| 3:52〜4:05 | 締め「完成品のAIを配る仕組みではなく、人と一緒に育っていく、AIの土台を渡す仕組み」 | 主語をWorld Model Seed Systemにすれば、そのまま使える |

画面デザイン、植物が育つ比喩、「完成したAIを渡すのではなく経験から育つ」というメッセージは残せる。直すのは主にラベルと論理構造。

v2の作業順は、原稿 → ナレーション生成 → タイミング取得 → 各シーンの再構成 → 書き出し。ナレーション生成では、CURRENT.mdの共通制作ルール（前後の「はい」＋ロングポーズ）を適用する。

v2の制作ソースは、今回のようにリポジトリ外だけに置かず、リポジトリにも残す（置き場所は制作時に決める）。

### v2の説明構造

```text
World Model Seed System
共通の育て方・安全原則

        ↓ 個別化

Organization / Role / Project   どんな仕事・環境か、どこまで触れるか
Personal Context / Experience   その人が何を知り、何を経験したか
Task Contract                   今回何をして、どこまで任せるか

        ↓

World Model Seed
その人と仕事しながら育つ個別のAI作業単位

        ↓ 実務

Observation「何が起きた？」
  ↓
Discovery「ここから何が分かった？」
  ↓
Human Review
  ↓
World Model（複数の仕事でも使える判断原理）
```

後半は `context/ACTOR_WORLD_MODEL.md` の流れと昇格条件に揃える。

植物の比喩は、Systemを「育て方（土と手入れ）」、個別のSeedを「鉢ごとに育つ芽」に置き換えると、既存の素材を活かせる。

Persona、Human Signature、Promotion Harness、共通意味文法は、新人向けv2から外す。必要になった概念だけ、後から別名で検討する。

### 2本に分ける

- **入社案内ページ用（60〜90秒）** — 思想だけ。「この会社では、完成したAI社員を配りません。あなたと一緒に仕事をしながら育つAIがあります。」
- **入社オリエンテーション（3〜4分）** — World Model Seed Systemの4層と、経験から育つ流れまで。現行4:05版の素材を作り直して使う。

## 次の実験：説明なしで1人に通してもらう

実際の非エンジニア1人に、口頭の説明なしで入社案内から始めてもらう（実装前はこのワイヤーと `docs/REAL_MEMBER_ONBOARDING.md` を使う）。

```text
どこで止まった？
  ↓
なぜ止まった？（ページ / Codex / GitHub / 用語のどれの問題か）
  ↓
必要最小限だけ修正
```

新人が迷った場所そのものをObservationとして記録し、ページ・onboarding・World Model Seed Systemへ戻す。仕組みを、その仕組み自身で改善する最初の本番実験として扱う。
