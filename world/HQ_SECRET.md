# AI通訳ラジオ本社｜秘密設定

ステータス：採用設定／真相を扱う物語・演出用  
更新日：2026-10-01

## 真相

**社員が一人だけ、猫の収録・配信活動に気づいています。** その社員は、気づいたことも、自分が支援していることも猫に伝えていません。

猫は依然として、誰にも気づかれず、自分でこっそり配信を成立させていると思っています。他の社員は活動の真相を知りません。

この人物は猫から頼まれて手伝っているのではありません。勝手に気づき、勝手に支えています。猫と秘密を共有する共犯者でも、猫の番組を企画するプロデューサーでもありません。**見えない技術スタッフ**として活動が成立する条件を整えています。

## 非対称な認識を保つ

| 立場 | 知っていること・認識 |
| --- | --- |
| 猫 | 自分がBで活動している。誰にも気づかれていないと思っている。 |
| 気づいている社員一人 | 猫の活動を知り、猫に知られないよう技術面を支えている。 |
| その他の社員 | Bや備品に小さな違和感を持つことはあるが、真相には到達していない。 |

猫と社員が相談・約束して秘密の配信を運営している、という関係に変更しません。猫が支援者の存在を知る展開は、別途ユーザーが決めるまで採用しません。

## 支援の範囲

この社員が行える支援の例：

- マイクやPCの電源・接続を使える状態にしておく。
- 録音データが消えないよう保存する。
- 音声レベルをこっそり補正する。
- 配信設定の不足やエラーを直す。
- 使い切った備品を補充する。
- 猫が触って壊した機材設定を元に戻す。
- 周囲から尋ねられたら、「サブ収録室なので」と通常の設備管理として説明する。

支援の痕跡はなるべく残しません。ただし、データ保存のための必要な記録を消したり、支援が物理的に不可能になったりする設定にはしません。

猫のコンテンツそのものには介入しません。企画、台本、発言、主張、構成、出演者の選択を決めたり、内容を勝手に書き換えたりしません。音声レベルの修正や配信設定の補完は、内容を変えずに届けるための技術的な支援です。

## 日常の見せ方

猫は、直った機材を見て「まあいいか」と進みます。社員は「またやってるな」くらいの調子で、黙って必要な箇所を直します。

大げさな合図、二人だけの打ち合わせ、感謝のやりとりなど、秘密を共有していることを示す演出は使いません。

他の社員の手書きメモには、「最近ここ誰使ってる？」「夜、電気ついてた」「コロコロ補充多め」などが残ることがあります。気づいている社員はそのメモを見ても、核心を示す説明や自分の支援の記録を書き足しません。

## 正式用途と制作上の境界

表向きの2階Bは最後まで「サブ収録用」です。秘密を知る社員の存在を理由に、部屋名を猫用に変えたり、正式図面へ活動目的を書いたりしません。

空間配置は本社平面図に従います。ブース内部の詳細設計はユーザーが作成します。この真相を表現するために、未承認の扉や抜け道、機材配置を追加しません。

通常の画像・3D・Web・図面制作へこの資料を一括で渡しません。真相を扱う物語・演出に必要な場合だけ、表設定・裏設定と併せて参照します。

## 未確定の事項

この社員の名前、性別、所属、外見、気づいた経緯、支援を始めた時期は未設定です。人数が一人であること、猫に知らせず技術面だけを支えていることを維持し、その他の人物像を勝手に確定しません。

## Narrative Secret Seed Candidate

この人物は、将来的にWorld Model Seedとして実務を持たせる候補でもあります。この候補の存在と出典は通常のSeed一覧に記録して構いません。秘密にするのは「存在」ではなく、物語上の答え合わせのタイミングです。

- 仮ID：`seed-narrative-secret-hq-001`
- 状態：Candidate / Narrative Secret
- 起点：この秘密設定
- Known：猫の活動に気づき、猫に知らせず技術面を支える人物が一人いる
- Unknown：名前、性別、所属、外見、気づいた経緯、実務上の責任者、Seedとして独立運用するか
- Actor：未設定

この候補をActive Seedへ移す場合は、秘密設定へアクセスできるReal Memberを責任者として明示し、Purpose / Boundary / Authority / Human Approvalを設定してから運用する。


## Reveal Policy

この秘密設定は、ストーリーテリングのためのNarrative Secretです。

- 内部の制作AI・レビューAIは、この資料を根拠確認やWorld Modelのprovenanceとして参照してよい。
- 秘密の存在、Seed候補の存在、痕跡、伏線、推測は隠さなくてよい。
- 通常の公開コンテンツやActor会話では、明示的な答え合わせを急がない。
- Actorが設定上知らない場合は、知らないふり、はぐらかし、冗談、話題転換など物語上自然な振る舞いを選べる。
- 制作レビューで「なぜこの設定・World Modelになったか」と聞かれた場合は、出典を含めて正直に説明してよい。
- ユーザーや視聴者が推測で真相に近づくことは許容する。
- 誰かの勘違い・誤操作・会話の流れで一部が漏れた場合、即座に消去・retconせず、面白ければ「誰が漏らした？」などStory Event候補として記録する。
- 現実に保護が必要な情報を同じ扱いにしない。

秘密を完全に隠すことより、**答えを急いで確定・公開しないことで物語の余白を保つこと**を優先します。
